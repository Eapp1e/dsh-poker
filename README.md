# dsh-plugin-poker

**德州扑克牌桌：模型可调用的扑克工具、六种内置策略对手、可选的教练层，以及一个浏览器牌桌面板。**

*Texas Hold'em table for DeepSeek Harness: model-callable poker tools, six heuristic opponents, an optional coach, and a browser table whose buttons never post a chat message.*

德州扑克（无限注 Texas Hold'em）插件 for [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)。

一个包同时提供两半：

- **Host 半**：确定性德州扑克引擎 + 6 个模型可调用工具（开桌/行动/看牌/下一手/机器人决策/胜率）。
- **Client 半**：Web GUI 里把每次扑克工具调用渲染成可视化牌桌卡片（底牌、公共牌、底池、各家筹码、行动按钮）。

你在对话里用自然语言出牌（“跟注”“加注到 400”“弃牌”），模型调用工具推进牌局；牌桌状态由引擎维护，机器人对手由内置策略自动打，也可以临时交给模型决策。

安装（一行，声明了 `dsh.bundle`，装完重启 `dsh web` 并刷新页面）：

```bash
dsh plugin --profile web add dsh-plugin-poker
```

零运行时依赖、零构建步骤、`npm test` 自带 6 个套件 940+ 条断言（含一套**打包契约**测试，把"能不能被插件列表收录"也钉住了）。
想把它列进 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) 请看 [`SUBMISSION.md`](SUBMISSION.md)。

## 快速开始

### 1. 安装到某个 profile

**方式 A：作为 bundle 安装（推荐，适合正常分发）**

```powershell
# 从 npm（发布后）
dsh plugin --profile web add dsh-plugin-poker

# 或者直接从本地仓库目录
dsh plugin --profile web add link:<本仓库路径>
```

`dsh plugin` 会转发给 profile 目录下的 pnpm，并把声明了 `dsh.bundle` 的依赖自动加入 `dsh.profile.bundles`
（本包声明了 `cordis.patch.yml`，因此会被自动激活）。这种方式需要**重启宿主**：新的 bundle 层在启动时组合。

**方式 B：手工加一行（无需重启，适合开发）**

把包放到 profile 能解析到的位置（例如 link 进 DSH 安装目录的 `node_modules/`），
然后在 `$DSH_HOME/profiles/<profile>/cordis.patch.yml` 里加：

```yaml
- insert:
    - id: poker
      name: 'dsh-plugin-poker'
```

profile 的 `patchReload: live` 会在文件变化时重新组合，**无需重启宿主**即可加载。
两种方式**只能选一种**：既做为 bundle、又在用户 patch 层加行，会加载两次并在工具名上冲突。

### 2. 刷新浏览器页面

客户端（牌桌卡片）的 boot graph 是在页面 HTML 渲染时注入的，所以**首次安装后必须刷新一次页面**。
之后改 `lib/client.js` 时，客户端 HMR 会在约 500ms 内把新 bundle 原地换进页面，**不用再刷新**；
宿主侧 `lib/*.js` 的改动下一次点击/工具调用就会生效，**不用重启**（见「改完代码不用重启：热重载」）。

### 3. 开一桌

直接跟模型说：

> 开一桌德州扑克，3 个机器人，起始筹码 5000，盲注 25/50

或者自己触发工具 `poker_new_table`。之后用自然语言出牌即可：

- “跟注” / “过牌” / “弃牌” / “全下”
- “加注到 600”
- “我现在胜率多少？”
- “让机器人认真想想再打”（切到模型接管模式）

面板下方的 **🎓 教练窗口**会实时讲这一手该怎么读、为什么这么下注；想全凭自己分析，点一下 `💡` 教学开关就能整层隐藏。

## 工具一览

| 工具 | 作用 |
|---|---|
| `poker_new_table` | 开桌并发第一手牌。玩家坐 0 号席位；可选机器人数（1–8，即 2–9 人桌，默认 5 = 六人桌）、性格、起始筹码、盲注、随机种子、对手脑袋。 |
| `poker_action` | 代表玩家执行动作：`fold` / `check` / `call` / `bet` / `raise` / `allin`。**`amount` 是“加注到”的本轮总额**，不是加注差额。 |
| `poker_next_hand` | 当前手结束后发下一手。玩家破产或只剩一人有筹码时牌局结束。 |
| `poker_table` | 读取当前牌桌状态（含可选行动与最近牌局记录）。`reveal: true` 仅供调试，会显示所有机器人底牌。 |
| `poker_opponent` | 双用途：只传 `brain` 切换机器人脑袋（`auto` 内置策略 / `model` 由模型逐手决策）；带 `action` 则为当前等待决策的机器人提交动作。 |
| `poker_equity` | 蒙特卡罗模拟估算某席胜率（对抗未知底牌），默认 1500 次。 |

机器人性格：`rock` 岩石 / `tag` 紧凶 / `lag` 松凶 / `station` 跟注站 / `maniac` 疯子 / `pro` 老练。
`botStyles: 'mixed'` 会轮换搭配。

## 玩法与规则实现

### 对手怎么打（以及它们的取舍）

六个性格（岩石 / 紧凶 / 松凶 / 跟注站 / 疯子 / 老练）共用一套**按价格与局面**的决策，性格只调它的松紧、激进度与诈唬率：

- **翻前按位置开池**（`OPEN_BY_BEHIND`：后面人越多开得越紧），面对加注时**按价格决定继续范围**：
  3BB 这种小加注要宽防（约 top 35-45%），10BB 以上的大加注收窄，**压上全部筹码的加注只跟 top 15% 左右**。
  早期版本对小加注也只用同一套窄范围，加上"没人加注就弃牌"，实测**80% 的牌局在翻前就结束了**；
  现在这个数字是 ~72%，翻牌/摊牌率从 3% / 13% 升到 4% / 19%。
- **面对大注要看真实胜率，而不是"价格划算"**：`worthThePrice` 拿牌力分和底池赔率比大小，
  而**全下/大注的范围只有强牌**，所以现在**全下只跟有真东西的牌**（两对以上，或小 SPR 的成牌）；
  一次全下被半个桌子用 A 高跟掉的场面就是这么来的，现在有单测钉住（空气牌必弃、三条必跟）。
- **翻后**用牌力 + 听牌价值 + 位置，河牌不再把"四张同花"当听牌（那时它只是一手高牌）。

> 这些数字都是无头跑的实测（30 局 × 200 手，六个性格轮换）：翻前结束 72%、翻牌 4%、摊牌 19%，
> 筹码总量守恒。牌局会随着时间把筹码集中到一个人手上——不补码的牌桌本来就是零和的，这一点不是 bug。

### 规则细节

- 无限注；大小盲；单挑时按钮位下小盲且翻牌前先行动（位置规则与标准一致）。
- 最小加注 = 上一次加注幅度；**不足额的全下加注不会重新打开下注轮**。
- 边池按投入分层计算，同资格层的池自动合并；平分时的零头按“按钮左侧优先”分配。
- 无人能跟的多余下注在结算前退回（uncalled bet refund）。
- 所有人都全下时自动一次发完剩余公共牌并摊牌。
- 牌力评估：7 选 5 穷举，返回类别 + 踢脚，可比较整数分数（同花顺 > 四条 > 葫芦 > 同花 > 顺子 > 三条 > 两对 > 一对 > 高牌，含 A-5 轮子顺）。
- 随机数使用状态内 PRNG（mulberry32），**整局可从日志完整复现**：同样的种子发同样的牌。

```

  cordis.patch.yml    # bundle 层：插入一行 id=poker 的 Loader 条目
  lib/
    cards.js          # 牌、解码、种子 PRNG、洗牌
    evaluator.js      # 5/6/7 张牌力评估与中文牌型名
    engine.js         # 牌局状态机（下注轮、边池、摊牌、退款、超时保护）
    bots.js           # 内置策略对手 + 蒙特卡罗胜率
    render.js         # 模型可读的牌桌文本渲染
    coach.js          # 教练：读牌、下注逻辑、底池数字、复盘、概念课（**可关**）

    client.mjs        # Client bundle 测试：383 项断言（回放、发牌节奏、教练窗口、牌局记录、按钮、牌桌、规则拒绝不打字、补码卡、跨会话同步、侧栏面板）
    coach.mjs         # 教练测试：62 项断言（位置/牌型/补牌/读牌/赔率/连续开枪/建议动作/不泄露底牌）
    hot.mjs           # 热重载测试：24 项断言（改文件→同一进程内立即生效、牌桌不丢）
```

设计要点：

- **引擎是唯一事实来源**，工具只做参数翻译与渲染，不参与任何扑克计算。
- **入口层与实现层分离**（见下节）：`index.js` 只做注册与状态持有，所有扑克逻辑在 `impl.js` 及其依赖里，
  因此改逻辑不需要重启宿主。
- **牌局状态放在以 Session 对象为键的 WeakMap 里**：天然按会话隔离，随会话释放；不写会话日志。
- 每个工具返回 `{ text, view }`：`text` 给模型（也就是对话里看到的牌桌文本），`view` 是通过 `output.presentationMeta`
  持久化到 `tool/result` 的结构化快照，浏览器卡片直接读它。**卡片因此是纯函数**，不需要投影、RPC 或额外宿主接口。
- 对手策略由 `advance(state, decide)` 驱动；`decide` 抛错或返回非法动作时会退化为“能过牌就过牌，否则弃牌”，
  并计入 `stats.botFallbacks`，保证策略 bug 永远不会卡死牌桌。
- **牌面通吃（playing the board）是一个显式概念**：河牌圈公共牌本身就是完整的五张牌，如果某人的最佳七张牌**打不过公共牌自己**，
  他的底牌等于没参与成牌 —— 最多只能平分。`playsTheBoard()` 判定这种情况，`postflopStrength()` 直接给 0.08，
  并且所有宽松规则都**必须先通过牌力门槛**，只留一个很小的抓诈唬机会（`committed < 0.1`，且只有最松的性格）。这条规则来自一次真实翻车：
  跟注站拿着 2♣3♣ 在 4♠6♣6♥4♣K♠ 上跟了河牌的 650，因为“七张牌凑出两对”——那是**公共牌的两对**。
- **听牌只在「还有牌可发」时才算**。河牌圈的四张同花、四张顺子不是听牌，只是它们撞成的高牌 ——
  以前它们照样拿 0.33/0.31 的听牌下限，于是每一手没成的听牌在最后一条街都"值三分之一个底池"，是个纯送钱机器。
  现在河牌只看已成牌（同一手牌：转牌 0.33 → 河牌 0.27 的 A 高）。
- **下注尺度跟牌面走**（`boardTexture`）：**干燥面**（彩虹、不连）小注 1/3–1/2 池拿价值、诈唬也用小的；
  **湿润面**（两同花 / 连张）2/3–3/4 池保护价值、赶听牌；**公对面**取中间。实测同一手两对、底池 1000：干燥面下 600、湿润面下 800。
  这正是教练讲给玩家的那套话 —— 教练教的东西，机器人自己也照做，否则教学就不可信。
- **下注尺度也跟人走**（`tableRead`）：面对**跟注站**价值下注加价（600 → 750），并且**基本停止诈唬**
  （疯子对岩石 27% → 对跟注站 13%）；面对岩石/紧手才用诈唬。读牌不只读牌面，也要读对手是谁。
- **小 SPR 就打到全下**：SPR ≤ 3 且牌力 ≥ 顶对（0.5）时直接 all-in，而不是下一个"给听牌好赔率"的注。
  实测：三条 8 在 SPR 1.5 → all-in、SPR 30 → 正常下注 600；9 高即使 SPR 1.5 也照样过牌（短筹码不是全下的理由）。
  这条同样是教练的原话（"SPR ≤ 3：顶对可以打到全下"）。
- **翻前尺度标准化**：开池 2.4–3BB（随后面待行动人数微调，按钮位 AA 开池 2.5BB），
  **3-bet 有位置 3x、盲注位 3.9x**（先行动要多付钱），全部落在教练判"标准"的区间里。
- **教练读牌按「连续开枪」复利收窄**：一次下注可能是持续下注（c-bet）带空气，连续两条街下注就不是了 ——
  第二条街起把范围再乘 0.72，并在读牌文字里点名 barrel。同一手 A 高的胜率会因此从 ~50% 掉到 ~40%（模拟给出）。
- **翻后跟注比较的是「赔率」，不是「固定门槛」**。机器人先算这手牌值多少（`postflopStrength`：成牌档位 + 听牌价值），
  再算跟注需要多少胜率（`potOdds = 跟注 ÷ (底池 + 跟注)`），只有 **牌力 − 赔率 ≥ −允许误差** 时才跟；
  误差按性格松紧（紧的 1 分、松的 3 分）+ 位置 + 一点随机，**最多约 5 个百分点**；
  另外单独保留一条「便宜就跟」通道（需要胜率 ≤ 22%），所以小注仍然能被很宽的范围跟。
  这条规则来自另一次真实翻车：同一手牌里，松凶的石头拿着 **J♦T♦（J 高 + 卡顺听牌）在转牌跟了 4,550**，
  而底池只有 5,900（需要 30% 胜率，他的实际胜率约 15%）。原因是当时的规则拿牌力去比一个**固定门槛**、
  完全不看价格，而且卡顺被评成 0.34（几乎等于两头顺 0.42）；再加一条「跟注额不到三分之二就跟」的捷径，
  松凶性格有 78% 概率无脑跟。现在：同样的局面**所有性格都弃牌**，同样价格换成坚果同花听牌 100% 跟注，
  顶对/三条该加注就加注，四分之一底池的小注仍然照跟 —— `test/run.mjs` 里有一整组断言钉住这套行为。
- **听牌价值按「还能成什么」折算**：两头顺 0.42/0.31（翻牌/转牌）、同花听牌 0.45/0.33、
  卡顺 0.22/0.16、没配对的 A 高 ≈ 0.20–0.27（两张高牌有加成）。以前卡顺被算成 0.34，
  和两头顺几乎一样，这也是上面那次跟注的原因之一。
- **翻前是「范围 + 位置」决策，不是绝对门槛**。`preflopStrength()` 给出 0..1 的牌力，`preflopPercentile()` 把它换算成
  「在全部 1326 种起手组合里位于前百分之几」，然后按**身后还有几人待行动**查开牌范围
  （`OPEN_BY_BEHIND`：关池最宽、第一个行动最紧），再按性格松紧缩放；面对加注则用其 1/3 的范围 3-bet、0.9 的范围跟注。
  实测（500 手）：8 人桌前位 VPIP 18% → 按钮 38% → 小盲 49% → 大盲 93%，**77% 的手有非盲注玩家主动入池**。
  这修掉的是一个真 bug：早期版本每个位置都用同一个绝对门槛，满环桌上前位几乎把把弃牌，
  **整桌只有盲注和按钮在玩**（8 人桌只有 6% 的手有人主动入池）。
- 对子评分含一个 `+4` 的固定加成：纯 Chen 公式把 88 评得**等于** KQo，但对子有听三条与已成牌摊牌价值，
  所以 88 现在得 0.60、KQo 0.40（AA 1.00、22 0.30、72o 0.00）。
- `botBrain: 'model'` 时 `advance` 会在第一个需要决策的机器人处停下并写入 `pendingDecision`，
  由模型调用 `poker_opponent` 提交决定 —— 这样“让机器人认真打”不必为每个机器人动作都付一次模型请求。

## 改完代码不用重启：热重载

Node 会把 ES 模块缓存到进程结束，所以早期版本**每改一次 `lib/*.js` 都要重启宿主**——而重启会把内存里的牌桌全部丢掉。
现在改完存盘即可，下一次点击/工具调用就是新代码：

- **宿主侧**：入口层 `lib/index.js` 在每次工具调用和每次 `/poker/*` 请求时算一次「修订号」
  （`impl.js / engine.js / bots.js / cards.js / evaluator.js / render.js` 六个文件的 mtime + size 的指纹）。
  变了就把这六个文件**复制**到 `<系统临时目录>/dsh-plugin-poker-hot-<安装指纹>/<修订号>/`，
  再从那个目录 `import('./impl.js')`。复制整份是关键：`impl.js` 里全是普通相对导入，
  快照让新代码和它的**所有依赖**处在同一个修订上，绝不会出现「新引擎 + 旧牌型评估」这种混搭。
- **牌桌不丢**：`TABLES` 与「当前牌桌」都留在入口层，不参与重载，所以正在打的那手牌继续打，也不会因为一次热重载换到别的桌上。
- **改坏了也不会炸**：新修订导入失败（比如存了个写了一半的语法错误）时会**继续用上一份可用代码**，
  `hotState().lastError` 里有原因；改好之后下一次调用自动重载。
- **浏览器侧**：`lib/client.js` 由插件宿主按磁盘内容实时发出（带 `rev`），宿主的 client HMR 在 ~500ms 内把新 bundle
  **原地换进页面**（不用刷新）；页面的牌桌缓存挂在 `window.__dshPokerTables` 上，所以换 bundle 不会把牌桌打回旧状态。
- **只有两种改动仍然需要重启**：入口层 `lib/index.js`（工具清单、`/poker` 路由、牌桌注册表）和 profile 的 `cordis.patch.yml` 那一行。
  所有扑克逻辑、渲染、策略改动都是热的。
- 重载后牌桌上会出现一次 `🔄 代码已热重载 HH:MM:SS` 小药丸（`view.reload`），确认改动已经生效；
  `plugin.hotState()` 返回 `{ revision, loaded, staged, lastError }`，用于排查「为什么没热重载」。

这套机制在真宿主进程里验证过（临时加载一个探针插件，驱动真实工具、改 `engine.js`、再看修订号与药丸），
并且有独立测试：`test/hot.mjs` 用一份入口副本 + 桩实现断言
「改文件 → 同一进程内立即生效、工具注册没有重做、牌桌还在、坏文件回退、改好再重载」。

## 客户端 GUI

客户端半提供两个表面，共用一个牌桌渲染器：

**1. 对话内的牌桌卡片** —— 注册 `tool.call.toolview`，key 为六个工具名（该 key 域开放、未被官方占用，属于**追加式**注册）。
每次扑克工具调用那一行会被替换成当时局面的牌桌；两次调用之间的差异一眼可见。

**2. 侧栏常驻面板** —— 注册 `sidebar.footer.action`（list slot，`id: poker`），挂在**侧栏页脚**。
按钮上带一行实时摘要（`第 3 手·转牌 · 350 · 该你`），点开是一个 660px 的**浮动面板**，里面是**完整的当前牌桌**。
它读**两处**并取较新者：会话自己事件窗口里最新的一条扑克工具结果（`tool/result` 的 `meta.view`，必要时用 `tool/call` 反查工具名），
以及本页直接出牌时缓存下来的视图。牌局没开时它给出「开一桌」按钮。

> **为什么在侧栏而不是会话头部**：侧栏是**整个应用一份**的表面，而会话头部是**每个会话一份**。
> 放在会话头部时，切换会话就会把面板**卸载再挂载** —— 于是刚看完的一手会被"重播"一遍（进度一样，但要再看一次加载过程）。
> 侧栏只有一份实例，面板（连同它的开合状态、位置、回放进度）**跨会话保留**；面板内部用的是**一个固定缓存键**
> （`__dsh-poker-shared__`），所以哪次切换都不会重新排队回放。
> 组件在带 `sessionId` 挂载时仍然会去读那个会话的日志（把面板嵌回会话内也能用），不带就纯靠同步接口。
>
> 侧栏那颗按钮的图标是**画出来的黑桃**（内联 `svg`，`currentColor`），不是 emoji：
> emoji 在侧栏那种窄栏里会掉成一个小小的灰色单色字形，两边还随字体变样，正是"图标有点看不清"。
> 面板标题、每张牌桌卡片的标题、以及渲染失败时的占位行都用同一个标记 —— 只换一半会显得"改了个寂寞"。
>
> 黑桃装在一个**带边框的小方块**里（24×24、`border:.5px solid var(--dsw-alias-border-l3)`），
> 底色用 `--dsw-alias-fill-l2`（深色主题下是深色淡淡的灰、浅色主题下是浅浅的灰），
> 字形用 `--dsw-alias-label-primary`（深色主题下是浅色）—— 也就是**深色界面里"框内深、字浅"**。
> 早先这里用的是 `--dsw-alias-button-elevated-fill`（深色主题下也是一块亮底），配浅色字形就成了侧栏里最扎眼的一块。
>
> 整行**按侧栏自己的尺寸来**：`height:42px`、`border-radius:12px`、`padding:0 10px 0 8px`、`gap:8px`、
> `font-size:14px/22px`，hover 与打开态用 shell 的 `--dsw-alias-interactive-bg-hover/active`。
> 外层容器也照抄 `sidebar.settings` 的摆法（`width:calc(100% + 4px)` + `margin:4px -2px`）——
> 那 2px 就是两行图标对不对齐的差别。
> 侧栏只能放下一个图标时（`wide === false`）收成与其它 rail 按钮相同的 **36×36 圆形**，
> 够宽时才带上 `牌桌` 与那行摘要。

面板**不挡页面**：没有全屏遮罩，`position:fixed` 悬浮（默认右上角），**按住标题栏可拖动**到任意位置，
点击面板外部或标题栏的 × 关闭。于是你可以一手滚动/阅读对话，一手看着牌桌出牌。

### 牌桌长什么样

- **绒面 + 木边**：外圈是木纹圆环（`linear-gradient` + 内阴影），里面是放射状绒面（中心偏亮、边缘压暗），
  绒面上有一层**淡花色水印**（`♠ ♥ ♦ ♣`）和一圈虚线**下注线**，让椭圆看起来是张桌子而不是一块绿。
- **庄家按钮挂在持有它的那张座位卡上**（白色 `D` 圆片），位置**每一席都一样：卡片左上角**，
  一半压在卡片外沿，所以眼睛不用找，也永远不会盖住头像、筹码或底牌（试过"朝向桌心那一侧挂着"，
  每个座位方向都不同，反而更难认）。座位卡上的 `BTN` 与这枚 `D` **是同一件事**：`BTN` 是这个座位的**位置名**，
  `D` 是**实物按钮**（每手牌向左移一位，它左手边的人先行动）——鼠标停在 `D` 上或 `BTN` 标签上都会把这句话写出来；
  座位卡上带 `data-dealer="yes"`。
- **底池画成一摞筹码**：按真实牌桌看过去的样子画——**最上面一枚露出正面**（红色筹码体 + 一圈白色边缘点 + 白色内圈 + 中心点），
  下面三枚只露出**侧面的一道边**（每道 4px：白、绿、白），一眼就能数出是四枚。
  前两版把圆片摊平互相压着堆，两次都糊成一团颜色（用无头 Edge 把候选设计 9× 放大并排截图对比后选的这一版）；
  **侧面分层的"厚度"才是一摞筹码的样子**。
- **下注筹码**（座位上方那枚）改成"筹码片 + 金额"：左边一个小圆片，右边是 `250 (2.5BB)`。
- **公共牌是**一条**等距**的牌行：**只画已经发出来的牌**（没有虚线占位槽），五张牌一律 6px 间隔 ——
  之前给转牌、河牌多留 14px 想表示"街道分组"，结果那 6/6/20/20 的间距被读成排版错误，所以现在**只有一种节奏**，
  哪张是新发的由**逐张落牌动画**说明（见上「回放」）。
- **中央栏的顺序**：底池 → 公共牌 → **第 N 手/街 标题** → **需跟 X**（需跟紧跟在「第几手」下面）。
  **「需跟」是"玩家自己还差多少"**（`currentBet − 玩家本轮已投`），不是牌桌上的价格：
  你下注 200 之后，`currentBet` 就是你自己的 200，早期版本会把它当成欠款显示成「需跟 200」✗；
  现在**不欠就不显示**，被反加后才显示你真正要补的差额。
  座位卡挂在 49% 纵向半径上会伸出绒面，所以桌子**上下各留 62 / 66px 外边距**作为它们的落脚处 ——
  **桌沿与面板宽度保持原样**（660px 面板、11px 木框），只是上下多了呼吸空间。
  中央栏也**按最高的一张座位卡预留**：玩家卡会随着手牌进行长出「下注到 X」「一对 9」「赢 +450」这些行
  （无头浏览器实测最高 176px），所以中央栏放在 `top:47%`、行距 `gap:4px`、座位纵向半径 `49%`（满环 48%）。
  实测最坏情况（玩家既下过注、又被反加，于是"较矮的中央栏"和"最高的玩家卡"同时在场）仍有 **13px 净空**，
  平时（不欠款、需跟那行不显示）是 **23px** —— 早期版本这一格是 **−3px**，字会被自己的座位卡盖住。
  加上中央栏 `z-index:3`（座位 1）与窄桌缩牌，**「需跟」「第 N 手」这些字也不会被座位或牌盖住**。
- **牌桌被挤窄时会自己缩**：绒面整体是 CSS **container**（`container-type:inline-size`），
  桌子窄于 520px（会话栏被侧边栏挤压时的卡片）就自动把公共牌缩到 31px、座位牌缩到 27px、头像与字号同步收窄，
  中央栏加宽到 80% 并上移（`top:40%`），于是牌不会压到座位卡、发牌区也不会贴到你的座位。
- **每个座位是一张选手卡**：**头像**（按性格给表情：岩石 🪨 / 紧凶 🐯 / 松凶 🦊 / 跟注站 🐢 / 疯子 🤪 / 老练 🎩，玩家本人 🧑）、
  名字、**位置标签**（BTN 金色、CO 金色、SB/BB 蓝色、UTG/MP/HJ 中性；单挑显示 `BTN/SB`）、
  **这一街的动作术语**（open / 3-bet / bet / check-raise，见上「动作按扑克术语标注」）、
  筹码 + BB、底牌、成牌名、动作、台词，以及弃牌/出局的整体变暗。
- **鼠标悬浮座位会浮出教练对他的读牌**：标题是「老王 · 紧凶（…）」，正文是这一手他每个动作的解读与
  "当前估计范围宽度约 9%" —— 和教练窗口里的读牌是同一份数据（宿主在读牌条目里带上了 `seat`，
  所以悬浮哪个座位就显示哪个人的读牌，不需要按名字猜）。玩家自己那张不显示（那是你的手牌）。
  读牌卡是 **214px 宽**，所以它**挂在哪一边由座位自己决定**（`data-read="above-left"` 这样的值）：
  上半圈的座位朝**下**开（朝上会跑出绒面被面板裁掉），最左/最右的座位**贴边开**而不是居中 ——
  测试按 640px 绒面把每张读牌卡的方框算出来，断言它**完整落在绒面内**。
  座位 DOM 上另外带了 `data-seat` / `data-style` / `data-position` / `data-human` / `data-read`，方便调试与自动化。

**📌 固定**：标题栏的固定按钮把面板钉住 —— 固定后不可拖动、点外部也不会关闭，只有 × 或再次点固定才收起。
**位置与固定状态都记在 `localStorage`**，下次打开（含刷新页面）会回到你放的位置。

牌桌外观：**标准椭圆桌** —— 木质桌沿包着绒面，**各座位环绕桌沿**（你固定在底边中央，座位号沿引擎的行动顺序逆时针排布，所以下一位行动的人永远在你左手边），
底池与公共牌在桌子正中；牌面带点数与花色（红黑分色）、对手牌背、押注筹码角标、**当前牌型**（如“一对 K”）、
当前行动者金框、赢家绿框、庄家/盲注/全下徽章、机器人台词。
手牌结束后赢家卡上会挂一枚绿底结算徽章 `+450`：**加号是独立的一块**（12px/800，比后面的数字大一号并单独居中），
所以它读起来是"加了 450"，而不是"450 前面多了个小点"。

**几何按人数自适应**（满环时两侧各要竖排 3 张座位卡，扁桌子必然重叠）：桌子高宽比随人数变化
（≤6 人 1.78、7-8 人 1.45、9 人 1.32），纵向半径同步放大，**座位卡保持全尺寸**（放大桌子，而不是缩小卡片；
牌面、字号、内边距都不缩）。**座位往桌沿再挪了一点**（纵向半径 ≤6 人 47%、7 人以上 46%），
所以**上方座位卡的下沿和中央底池之间留出空档**（实测 640px 宽六人桌：底池上下都没有卡片压着，
中央栏底部到玩家卡 18px 以上、玩家卡底部到行动区 31px）；因为卡片伸出去更多，桌沿留白同步改为：
`data-seats="9"` 用 48/52px、`7/8` 用 52/56px、`≤6` 用 62/66px。
**座位卡内部也留了气口**（`padding:6px 7px`、行距 `gap:3px`；窄面板的 container query 才收紧回 3/4px 与 1px），
名号 / 徽章 / 筹码BB / 牌面四行不再贴在一起。
另外**在场的座位卡永远画在弃牌者之上**（`.dshp-seatOut` 的 `z-index:0`，行动者 5，悬浮 6）：
九人桌两侧的卡片挨得很近，压住一点点的时候，赢家必须是"还活着"的那张。
**牌桌不会被滚走**：面板是纵向 flex 列，桌子 `flex:none` 保持尺寸，**底栏拿固定预算**（150–236px，
两列按 `align-items:stretch` 拉满行高）——左侧「教练建议 + 行动区 + 下注区 + 尺度助手」保持**原来的整宽布局**
（不加内边距、不套第二层卡片，否则一行按钮会被挤到换行），右侧「牌局记录」是 214px 的卡片
（原来 252px，省下的宽度全给左侧）。两列各自 `overflow-y:auto`，而且**滚动条是细的、平时完全透明**：
宽 6px（`scrollbar-width:thin` + `::-webkit-scrollbar{width:6px}`，Windows 默认那根占 17px，会把窄栏挤得很难看），
默认滑块 `background:transparent`，**只有指针真的落在那一小条上才显示**（滑块自身 `:hover` 0.6、`:active` 0.85），
**把鼠标移到内容上不会让它冒出来**——模块看着就是一块内容，而不是旁边常年挂着一根轨道。
（Firefox 没有分部件样式、也无法"悬浮才显示"，所以用 `@supports not selector(::-webkit-scrollbar)` 给它一根 0.4 的淡滑块。）
面板本身（窗口太矮时才会滚）和教练窗口同规则。
**每列只有这一层滚动**（牌局记录本身不再自带滚动条），拖动阅读时绒面纹丝不动。以 640px 宽为准：

| 人数 | 桌面高 | 两侧相邻间距 | 座位卡高 |
|---|---|---|---|
| ≤6 | 360px | 155px | ~87px |
| 7-8 | 441px | 131 / 131px | ~87px |
| 9 | 485px | 137 / 121px | ~87px |

测试里直接按坐标算像素间距并断言 ≥90px，防止以后改样式又叠上。

支持 2–9 人桌（`botCount` 1–8，默认 5 即六人桌；填 8 就是九人全环）。

### 一切金额都带 BB

德州扑克的通用思考单位是大盲，所以每个关键数字旁边都给出 BB 换算，并且刻意做得**醒目**（浅蓝底的小药丸，不是灰字）：

- 座位：筹码 `10,000` + `100BB` 药丸；本轮投入的筹码角标 `100` + `1BB`（金底上用深色药丸保证对比度）
- 牌桌中央：底池 `💰 350` + `3.5BB`、`需跟 100 (1BB)`
- 行动按钮：`跟注 100 · 1BB`、`全下 9,900 · 99BB`
- 尺度助手：`1BB = 100`（明示本局换算率）

**加注金额有两种输入**：左边按筹码、右边按 BB，**两边实时联动**：
筹码框的上下箭头**每次 1BB**（`step = 大盲`），BB 框直接输入例如 `3` 就会把筹码框写成 `300`（大盲 100 时）。
于是可以完全用 BB 思考，也可以精确到筹码。

### 下注尺度助手（教学）

当轮到你下注/加注时，控制条下方会出现一个**尺度助手**：

- **四个标准尺度按钮**：`1/3 池`、`1/2 池`、`2/3 池`、`1 池`。每个按钮直接显示**本轮的总额**与 BB，
  下面一行写明它用在什么场合（干燥面价值 / 最通用的价值尺度 / 湿面价值+保护 / 极化：很强或纯诈唬），悬停还有完整说明。
- **点击尺度只填金额框，不出牌**：看清数字和 BB 之后，再点“下注/加注”确认。两步走本身就是练习。
- **动作按扑克术语标注**：每个按钮带一个术语标签（`check` / `call` / `all-in` / `fold`），
  加注一类还会**按局面报出正确名称**——翻牌前无人入池是 **`open` 开池**、对开池再加注是 **`3-bet`**、再往上 `4-bet`；
  翻牌后则是 `bet` / `raise` / `check-raise`（你先过牌、对手下注后你再加注）/ `re-raise`。尺度助手标题重复该名称，悬停给出定义。
  **对手也一样**：谁在这一街 open / 3-bet / 下注 / 过牌-加注，他的**座位卡上就戴一枚同名的术语药丸**
  （`data-term="open"`，翻前蓝底、翻后琥珀底），以前那里只写「加注到 300」——是数字，不是动作。
- **每个动作按钮有自己的颜色**：过牌**青绿**（`#0f8f86`，以前是和尺度预设一样的灰，两排看着像一组控件）、
  跟注绿、加注蓝、全下紫、弃牌红；每个都用自己的颜色做 hover / 按下。
- **金额框**：筹码框的上下箭头步进 1BB，右侧 BB 框可直接按 BB 输入（双向联动），`✕` 一键清空；
  确认按钮上的金额随输入实时更新（直接改 DOM，不需要重渲染）。
  **确认按钮的「动词」和「金额」是两个独立元素**，窄的时候金额会**换行到第二行**而不是被截断
  （以前金额一大就显示成「加注到 1,...」，偏偏那是最需要看清的数字）。
- **尺度按底池计算**：开池是 `比例 × 底池`，加注是 `当前注 + 比例 ×（底池 + 跟注额）`——所以“1 池”就是标准的 pot-sized raise。
- **牌面判读**：一行实时结论，如“湿面（同花面）：听牌多，下注要大一点保护价值——建议 2/3 池至 1 池”，
  由公共牌的花色集中度、连张与公对自动判定（干燥面 / 连接面 / 同花面 / 公对面）。
- 另外：`跟注` 按钮的悬停提示会给出**底池赔率**（“需要 25% 胜率才划算”），`全下` 的提示说明适用条件（短码或极强牌）。

**版面**：牌桌下方是一条**两列底栏** —— 左边是策略区（胜率条 + 行动按钮 + 尺度助手），右边是**牌局记录**侧栏（摊牌结果 + 最近 12 条记录，可滚动）。
记录不再堆在整块 UI 的最底部。

行动区是**三层紧凑结构**：

1. **一行动作按钮**：`过牌` / `跟注` / `全下` / **加注（在弃牌左侧）** / `弃牌`，每个都是两行式——第一行中文与金额，第二行小字放 BB 与术语（`跟注 100` / `1BB · call`）；
   **四个按钮宽度完全一致**（`flex:1 1 0`，加注键不再比别人宽 1.5 倍）；
2. **下注工具条**：`[↺ 重置] [金额] 筹码 = [BB] BB ≈ ×池`。金额框**紧凑但保留原生上下箭头**
   （`flex:0 1 84px`，BB 框 66px：箭头按一个大盲步进，是这一行唯一的"微调"手段，所以不能删），
   右侧的 **`≈ ×池` 固定 74px 宽 + 等宽数字（tabular-nums）**，所以打字时"0.4 池 → 1.33 池"只在原地变字，
   **整行不会跟着伸缩**；它**紧跟在 BB 框后面**（不加 `margin-left:auto`：为了把一个两字标签推到行尾而撑出一大段空白，看着像排版出错）；
   加注按钮用**蓝色强调色 + 向下三角**指向这一行，两者同一配色，视觉上是一组；
3. **尺度助手**：四个尺度按钮排成对齐网格（`auto-fit minmax(148px,1fr)`），下面一行牌面判读。

**文字装不下就换行，绝不截断**：每一行标签都是**整词列表**（`跟注` + `8,025`、`80.3BB` + `all-in`），
容器是 `flex-wrap`，所以窄按钮里金额会**落到第二行**，而不是变成 `全下 8,0...`
（整词外层仍是 `nowrap`，绝不会出现逐字竖排那种碎字）。

**尺度助手把"按哪个底池算"写在脸上**：标题栏给出这次要用的分母，例如
`底池 150 (1.5BB) · 需跟 100 (1BB) · 下注按此算 · 1BB = 100`（开池）或
`底池 450 · 需跟 300 · 加注按跟注后 750 算 · 1BB = 100`（面对下注），
每个预设的悬停说明再写出完整算式，例如
`1/3 池：跟注后底池 750（底池 450 + 需跟 300）的 1/3 = 加注 250，本轮总额 550 (5.5BB)`。
两个约定固定不变、并有测试守着：
**开池（本街还没有人主动下注）= 下注前底池 × 比例**；
**加注 = 当前注 + 跟注后底池 × 比例**（所以 `1 池` 就是标准 pot-sized raise）。
"是不是开池"看的是**牌局记录里这一街有没有人下注/加注**，而不是"当前注是不是 0" ——
翻前的大盲是强制投入、不算有人下注，所以 1.5BB 的底池里下 2BB 会读作 **1.33 池**（而不是以前那个 0.4 池）。

**翻前（以及"比例会塌成同一个数"的局面）改用大盲做单位。** 翻前的底池就是两个盲注，
任何"几分之一池"都低于最小加注，于是四个预设会**塌成同一个数字**（都写着"最小"）——
每个新一手的第一次下注看到的都是这个，看着就像坏了。现在这种局面改成按大盲给：
开池是 `2.5BB / 3BB / 4BB / 6BB`（小开池 / 标准 / 隔离 / 大尺度），
面对加注是 `2.5× / 3× / 4× / 5×`（当前注的倍数，也就是"3-bet 到 9BB"那种说法），
每个预设的悬停里同时写出它约等于几个池（读数仍然按池算，跨街比较才有意义）。
翻后第一次下注（c-bet）不受影响，仍是 `1/3 / 1/2 / 2/3 / 1 池`。
两个边界也一直会说明白：低于最小加注时预设落到最小加注，子标签显示 `最小 · …`、悬停里注明"实际约 ×池"；
超过全下上限时子标签显示 `全下 · …`。

### 对手行动的过程与动效

引擎是**一次性同步跑完**机器人行动的，所以早期版本里对手的动作是「瞬间跳到结果」。现在宿主会把**这一手每个动作**连同落点数据一起返回：

```json
{ "ok": true, "view": { }, "steps": [
  { "seq": 7, "seat": 2, "action": "call", "amount": 100, "label": "跟注 100",
    "street": "flop", "board": ["As", "8d", "Ad"], "stack": 9900, "streetCommitted": 100, "pot": 300, "currentBet": 100, "talk": "看一眼不亏" }
]}
```

- `seq` 是**全桌单调递增**的动作号（跨手不清零），客户端只回放 `seq` 大于「已展示到」的那些，不会重播旧动作。
- 每个 step 自带行动者的筹码、本轮投入、底池、当前注、台词、**街道与当时的公共牌**，**回放不需要客户端有引擎**。
- 客户端按**真实牌桌的节奏**逐步应用：**每一拍都等一拍**，包括你自己（0 号席）的动作 —— 每步 **约 820ms**（同一街内还有 ±110ms 的小抖动，
  下注/加注再 +200ms，避免像节拍器一样整齐）；**换街后的牌是一张一张发的**：第一张先停 **1500ms** 让街道落地，
  之后每张 **620ms**，所以翻牌看得到三张牌分别落桌、转牌河牌各一张（`dshp-dealIn` 落牌动画只作用在**这一拍新出的那张**上）。
  发牌本身不推进 `3/12` 进度（那不是动作），但会计入 **26 秒总预算**（每步不短于 240ms），超过 120 个未展示动作时才会丢弃最旧的。
  > 自己的动作**以前是 0ms 立即生效**，理由是"点击已经发生了"。但一手牌**开局**常常轮到你先说话，
  > 于是你的筹码瞬间跳走、接着每个机器人都慢一拍，整桌看起来像坏了 —— 现在你和所有人同拍。
  > 同时出手瞬间就把 `legal` 置空（`resolving`），所以那 0.8 秒里不会有人点到过期动作。
- **弃牌之后整手牌继续打完**：宿主一次性跑完机器人行动，回放把 `seq` 之后**每一个**动作都走一遍，
  所以弃牌后仍然能看到翻牌、转牌、河牌和摊牌，而不是直接跳到结果。
- 回放期间：**行动者座位金框脉冲**（`@keyframes dshpSeatPulse`）、`legal` 置空所以**行动按钮暂时收起**、
  控制区显示 `⟳ 对手行动中… 3/12 · 加注 300` 的**进度与当前动作**，避免在牌桌未落定时点到过期动作。
- 回放结束落到宿主给的权威视图。**最新那张工具卡片会跟随实时牌桌**（它的 revision 在回放 chain 里），更早的卡片保持历史快照不变。

### 教练：可选的教学层

教练是**一个独立窗口**：默认停在屏幕**左侧**（牌桌面板默认在右侧），可以拖到任何地方、`📌` 固定、`×` 关掉，
位置单独记住（记在屏幕外的坐标会被拉回可见范围；两个窗口的布局互不影响）。它不挤在牌桌面板里，
所以牌桌永远只有牌桌——牌桌面板标题栏就是一排**同一种**图标按钮：`💡` 教学、`🔄` 换桌、`📌` 固定、`×`，
教学在最左、固定在最右。教学和固定用的是**同一套按钮样式**（同一个 `dshp-iconBtn`：同样的尺寸、悬浮、
以及"开着"时的琥珀色高亮），所以整条标题栏看起来是一条工具栏，而不是"一个亮片加三个图标"。
窗口标题栏的决策标签**只写结果**（`弃牌` / `跟注` / `加注` / `下注` / `过牌` / `全下`，按语气着色），
完整那句（"弃牌：K9s（同花）在关池位 CO 太弱…"）放进**悬停提示**，并在下面的「下注逻辑」一节里**完整展开**——
以前把整句塞进标签，窗口头部一行放不下就被截成"…太"，看着像坏了。
每一节都能点标题**折叠**，底部只有「收起全部/展开全部」（不再有位置说明文字），所以七节分析不会变成一堵墙。

点按钮后的**即时回执**：点击一发出，行动按钮立刻收起、原位显示 `⟳ 已发出，等牌桌回应…`，
等宿主的答复（以及随后的机器人回放）落地再恢复。以前按钮点完没有任何变化，看起来像"没反应"；
现在**同一时刻只可能有一次点击**，也不会重复提交。

`加注` 按钮在**金额框是空的时候按最小加注出手**：框里那个灰字就是最小加注（placeholder），
所以"直接按加注"= 加注到最小额。早期版本读的是框的真实值（空字符串），于是**按下去什么也不发生** —— 这是"点击加注没反应"的根因。

下注尺度助手只负责"把注额算出来"：四个预设按钮与动作按钮**同一套配色和悬浮效果**
（底色用主题 token `--dsw-alias-fill-l*` → hover 亮一档 + 亮边 → 按下更深）；牌面判读、建议文字与术语标签全部**移除**
（那些在教练窗口里，术语仍印在加注按钮的第二行 `open` / `3-bet` / `4-bet`），这一行只留底池/需跟/1BB 三个数字。
右侧「牌局记录」按街道分块：`发牌 · 翻牌` 这样的块标题带分隔线、底牌单独一格、行动拆成「谁 + 做了什么」
（名字是低调的浅灰，不再是显眼的金色）、台词用斜体灰字分开、摊牌行标淡蓝，最近 16 行滚动显示。

**四个动作按钮各自一个颜色家族**，都用自己的颜色做 hover（亮底 + 亮边 + 按下更深）：跟注绿、弃牌红、
加注蓝（与下面的尺度条同色）、**全下紫（`#6d4aff`）**——全下以前和尺度预设一样是灰的，现在不再混在一起；
加注与全下用的是**实色**底（不是半透明叠色），因为浅色主题下半透明底 + 近白文字会看不见。
**跟注键的绿是写死的 `#2f9e44`，不跟主题走**：它以前用 app 的 primary-button token，而深色主题里那个 token
是**近白色**，于是"跟注 300"变成白底白字，最常用的按键反而看不见了。弃牌仍然走 error token
（浅色 red-600 / 深色 #ec1313，底和字永远配套）。

**浅色主题也能读**：所有画在主题面板上的中性表面与文字都走 DSH 的 alias token
（`--dsw-alias-label-*` / `--dsw-alias-fill-l*` / `--dsw-alias-border-l*` / `--dsw-specific-menu`），
包括 BB 小药丸（`dshp-bbPane`）、状态徽章（`dshp-badgePane`）、等待提示、教练窗口与折叠三角；
只有**画在绿呢子上**的东西（座位、底牌、公共牌、底池筹码、庄家按钮、热重载药丸）保留固定的深色配色，因为那块背景永远是绿的。
**教练建议的高亮圈是黄色（`#ffd166`）**，故意不用蓝：加注键本身就是蓝的，用蓝圈会让人以为"这是加注键"而不是"这是教练的意思"。

**建议那句话必须自己回答"为什么"**：牌桌上只显示这一行，所以它写的是
`弃牌：A6o 在UTG太弱（后面还有 5 人）` 这种**带上具体牌型、位置和人数**的句子，
而不是"弃牌，等更好的位置或牌"（有玩家把后半句读成了术语"或牌"，来问那是什么意思）。
鼠标悬停这枚建议徽章会直接展开**理由与风险**（教练窗口里那几行），不打开窗口也能看懂为什么。
位置上的强弱判据是**翻前牌力百分位**：`topShare` 越小越强（AA 是 0.5%），
弃牌那档会在理由里把"比它强的牌还有很多、后面还有 N 个人没说话"讲清楚。

窗口里是**这一手的推理过程**，像有人坐在旁边给你讲。七个板块，全部由宿主实时算出来：

| 板块 | 内容 |
| --- | --- |
| 🧭 局面 | 你的位置（BTN/CO/HJ/UTG/盲注）、还有几人、后面还有几人行动、底池与 BB、有效筹码与 SPR、已投入比例 |
| 🃏 你的牌 | 成牌类型（超对/顶对+踢脚/中对/暗三/两对…）、是否用上底牌、每个听牌与补牌数、**2/4 法则**估算 vs 蒙特卡罗实际胜率 |
| 🎯 下注逻辑与建议 | 一句话建议 + 2-4 条"为什么" + 1-3 条"风险/反面"，并标注术语（open / 3-bet / c-bet / semi-bluff / value bet…） |
| 🔍 读牌 | 每个还在手的对手：性格、这一手每个动作、由动作与尺度推出的**范围宽度**与典型牌型、"他不太可能有什么" |
| 🧮 数学 | 底池赔率、需要的胜率、MDF 最低防守频率（翻后）、SPR、**对抗实际范围的胜率 ±误差** |
| 📝 复盘 | 你自己这一手的每个动作逐条点评（尺度是否标准、是否偏松、有没有漏价值） |
| 🎓 本手概念 | 按当前局面挑一张概念卡：底池赔率 / 补牌与 2/4 法则 / 位置 / 范围思维 / c-bet / 价值下注 / 半诈唬 / MDF / SPR / 阻断牌 / 隐含赔率 |

**建议是数据，不只是文字**：动作按钮上方会重复教练的那句话（`🎓 教练建议：弃牌`），
并给**对应的按钮加一圈高亮**。这样"金额框里预填了一个最小加注"只是控件，不会被误读成"教练让你 4-bet"——
2♦4♦ 面对 3-bet 时，高亮的是**弃牌**，窗口里的建议也是弃牌（`test/coach.mjs` 专门有一条断言守住这件事，
另有一条断言同样的局面换成 AA 就变成再加注）。

它的数字是**真的算出来的**，不是套话：

- **读牌是可量化的**：每个对手的范围宽度来自「位置 + 动作 + 尺度 + 性格」（例如紧凶开池≈前 17%、跟注≈前 26%、
  大注≈前 16%、河牌加注≈前 12%），然后把他们的范围**按当前牌面再筛一遍**——会用这种动作打的牌留下，纯空气被抽掉。
  胜率就是**对抗这个收窄后的范围**用蒙特卡罗（每手 150–600 次，按对手数缩放）算出来的，并给出 ±误差，
  所以面板上的"约 41% ±3%"是真有分布支撑的。尺度一律按**下注前的底池**折算（读牌日志里记的是累计投入，教练会还原）。
- **数学是标准公式**：底池赔率 = 跟注 ÷ (底池 + 跟注)；MDF = 底池 ÷ (底池 + 下注)；SPR = 有效筹码 ÷ 底池。
- **建议带条件**：多人底池里一对不再当价值牌打（面板会写"5 人底池里顶对只能算中等强度"），
  面对跟注站会提醒"诈唬无效、价值下注才对"，SPR 很小时提醒"强牌直接往全下打"。
- **不泄露对手底牌**：教练只看动作、尺度、性格和公共牌，`test/host.mjs` 里有一条断言：
  开启 `poker_table { reveal: true }` 拿到全部底牌后，普通视图（含教练文本）里**一张都不能出现**。

**可以整层关掉**：牌桌面板标题栏和每张卡片标题栏都有一个 `💡` 教学开关，一键关掉教学窗口、
建议高亮与牌面判读文字；关掉后只留牌桌、行动按钮和下注尺度预设（那是操作，不是教学），
选择记在浏览器里，下次进来还是关着的。模型侧也拿到同一份简报（`教练：…建议：…`），
所以它在对话里的解释和你在窗口里看到的是同一套数字，不会各说各话。

### 选人数开桌

面板没牌桌时直接显示**人数选择器**（大卡片网格）：`2 人（单挑）`、`3`、`4`、`5`、`6 人（标准）`、`7`、`8`、`9 人（全环）`——
点一下就用 `POST /poker/new { botCount }` **直接开桌**，不发消息、不等模型。
已经开着牌桌时，标题栏的 `🔄` 不再**替换**牌桌，而是在**卡片内部、绒面正下方**展开一条**换桌条**（`TableView` 的 `slot`）：
一排尺寸药丸（`2 人` … `9 人`，说明只在悬停提示里，不再写成"3 人 三人"）+ 右侧一颗 `取消`，
**当前人数的那颗高亮**（`.dshp-pickChipNow`），同时**标题栏的 `🔄` 图标会亮起**（与固定的琥珀色同一套状态）——
选中新尺寸就换桌，点取消就继续当前牌局，全程都看得见自己正在离开的那张桌子，也不会飘到面板外面去。

### 跨会话只有一张牌桌

牌桌**不属于任何一个会话**：宿主只维护一张"当前牌桌"（`lib/index.js` 里的 `CURRENT_TABLE` + `TABLES`）。
所以：

- 在任何会话里开桌，都会**替换**掉那张共享牌桌，其他会话立刻看到同一局；
- 任何会话的 `poker_table` / `poker_action` / `poker_equity` … 都作用在**同一张桌**上，
  不会出现"GUI 有一桌、模型说没有牌桌"，也不会出现"两个对话各打各的"；
- 浏览器侧，面板在**挂载时**和**每次打开时**都会同步一次，而且**分两种请求**：
  - 页面见过牌桌（本页操作过，或上次访问留下的记录）→ 直接按 id 问 `POST /poker/table { tableId }`。
    这是**每个版本都有的老接口**，所以**不重启宿主也能同步**：切到另一个会话立刻看到同一局；
  - 页面从没见过任何牌桌 → 才走新的发现接口 `POST /poker/current`（返回当前牌桌，没有牌桌时返回 `view: null`；
    老宿主上没有这个接口，控制台会留一行提示）。
  最近见过的牌桌 id 记在 `localStorage`（`dsh-poker-current-table`），刷新页面后同样能接上。
  - 这次同步**不会覆盖你正在操作的东西**：如果发现请求在飞行途中你点了按钮、或按钮刚被拒（面板上有红色提示），
    那个更新的本地状态优先，后台同步直接放弃这一轮。
- **模型工具**也共享这张桌（`poker_table` 在哪个会话问都是同一局）—— 这一半在入口层的注册表里，
  需要**重启一次宿主**才生效（客户端那一半刷新页面即可）。


**开桌/换桌后不会立刻开打**，都要按一下绿色的 **`开始`**（此时过牌/跟注/加注/弃牌与尺度助手都先收起来）。
这条链路由**两层**实现，所以**不需要重启宿主**也能生效：
1. **浏览器侧（主）**：`POST /poker/new` 的答案里本来就带着机器人这一轮的行动，客户端把它**扣住不发**，
   同时把画面**倒带**到刚贴完盲注的那一刻（每个人把投入的筹码拿回来、只留盲注，底池 = 两个盲注，公共牌清空，
   牌局记录只留开局与盲注两行 —— `handStartView`）。点 `开始` 才把这些动作**一拍一拍地放**（`releaseHeld`）。
2. **宿主侧（可选，重启后生效）**：`POST /poker/new` 干脆不推进机器人（`view.awaitingStart = true`，
   而且此时 `legal` 是机器人的、不会当成玩家的选项发出来），`开始` → `POST /poker/start` 才推进。
   两条路客户端都能走：有本地扣住的就本地放，没有就走路由。

模型走工具调用开的桌不受影响（照旧直接推进到该你行动）。

### 输光了怎么继续：补码

**只有当你的筹码归零时**，行动区才会换成一张**补码卡**（`.dshp-rebuy`，平时不存在）：
标题写 `你已输光筹码 · 补码后可发下一手继续`，下面给三档**整 BB 的补码额度**（`50BB` / `100BB` / `200BB`，
按桌子的盲注换算，例如 50/100 桌就是 `补码 5,000` / `10,000` / `20,000`），再往下是**自定义额度**输入框 + `补码` 键。
点一下就 `POST /poker/rebuy { tableId, amount }` —— 不发消息、不等模型，和别的按钮同一条路：

- 宿主 `opRebuy` 会**先检查你确实没筹码**（还有筹码会被拒：`你还有筹码，无需补码`），再把额度加到你的栈上、
  清掉 `out`/`allIn`、把牌桌拉回可发牌状态（`gameOver = false`、`phase = handover`），于是 `发下一手` 立刻能用；
- 补完码**补码卡自动消失**，行动区换回 `发下一手`；
- 补码是**加筹码**，所以整桌筹码总量会变大（这是补码的定义，不是守恒 bug）；
- 想换桌重来也行：标题栏的 `🔄` 一直在。

> 这一*只*在筹码归零时出现，是因为中途补码会让"当前的筹码量"失去意义 —— 它是破产后的一个明确选择，不是一个随时可点的按钮。

### 牌局结束：给一个"再来一局"

牌桌上只剩一个人有筹码时，引擎会进入 `gameover`：`canDealNext` 变 false、也没有任何合法动作。
早期版本在这种情况下**整个行动区什么都不画** —— 玩家只能盯着一张空桌子，没有任何出路。
现在这种情况会画一张**结束卡**：`🏆 你把全场打光了`（或"牌局结束"）+ 第几手，
加一颗 **`再来一局`** —— 它用**原样配置**重开（`botCount` / `smallBlind` / `bigBlind` / `startingStack`，
最后一项由 `view.startingStack` 带出来，所以重开的是同一局，不是默认局）。想换人数就点标题栏的 `🔄`。

### 发下一手：全场立刻刷新

`发下一手` 会开一手新牌，而**新一手的机器人行动仍然要一拍一拍地放**（否则你还没看清自己的底牌，一条街就过去了）。
难点在于：回放的**起点**必须是**新一手刚贴完盲注的快照**，而不是上一手的摊牌画面。
早期版本就是拿上一手的画面当起点，于是按下 `发下一手` 后：**座位上还是上一手的弃牌/亮牌/筹码，公共牌还挂着上一手的五张，
牌局记录也还是上一手的故事**，只有等每一拍（机器人的每个动作）落下来才逐个修正。
现在 `cacheView` 在**手数变化时**（`view.handNumber !== previous.view.handNumber`）用 `handStartView(view)` 当回放起点：
所有座位**立刻**复位（`folded = false`、`allIn = false`、亮牌收回去、各自只剩盲注、筹码回到手前水平），
公共牌清空、底池 = 两个盲注、记录只留新一手的开局与盲注两行 —— 然后再放机器人的动作。
`test/client.mjs` 里有一条断言直接钉住这件事（把起点改回旧画面就会失败：它会看到旧手数、旧公共牌和旧弃牌标记）。

### 按钮怎么出牌：直接打到宿主，不发消息

按钮（过牌 / 跟注 / 下注·加注 / 自填额度 / 全下 / 弃牌 / 发下一手 / 开始 / 补码）**不再往对话里发消息**。
每次点击是：

```
POST /poker/action   { tableId, action: "call" }
   → 宿主插件用引擎推进牌局（机器人自动行动）
   → 返回 { ok, view, text }
   → 页面缓存这个 view，面板与卡片立即重绘
```

- 路由由插件自己在 `apply` 时用 `webServer.register({ kind:'prefix', path:'/poker' })` 挂载（可选注入：没有 web 服务器的 profile 照常只有工具）。
- 牌桌用**不透明随机 id**（`view.tableId`）寻址，路由从不写会话日志。除了按 id 寻址的 `action` / `next` / `start` / `rebuy` / `table`，
  还有两个特殊入口：`new`（开一张新的共享牌桌）和 `current`（**发现**：当前牌桌；没有则 `view: null`）。
  `current` 是本机同源路由上的只读查询，作用是让任意会话都能找到那张牌桌。
- 每次变更都会递增 `view.revision`（宿主侧单调计数）。面板按 revision 在「会话日志里的视图」与「本页缓存的视图」之间取新者，
  所以点击出来的新局面不会被旧日志覆盖。
  > **换桌的坑**：`revision` 是**每张牌桌各自从 0 开始**的，所以"旧桌 revision 更高"并不是忽略新桌的理由 ——
  > 早期版本正是这么比的，于是点 `🔄` 换桌后新桌被当成过期快照丢掉，**换桌看起来完全没反应**。
  > 现在先比 `tableId`：换了桌子就整块换成新桌（不重放旧动作）；日志与缓存的取舍也先看
  > **日志里最新事件序号有没有超过缓存记录的那个序号**（点击永远不写日志，所以自己开的桌只有缓存里才有）。
- **兜底只给"路由根本没通"**：没有 web 服务器的 profile、网络失败、404 —— 这时同一个动作才退回成一条自然语言 prompt
  （控制台打印 `poker: the action route is unreachable, using the chat instead`），保证牌局还能继续。
- **规则拒绝不再写对话**：宿主回了 `{ ok:false, error }`（例如"加注必须高于当前下注"），说明**牌桌没问题、这一个动作不合法** ——
  这时面板会在按钮上方直接显示一条红色告示（`.dshp-notice`），**一个字都不进对话**，下一条成功答复就自动清掉。
  > 早期版本把"路由拒绝"和"路由不通"当成同一件事，于是**点面板按钮也会往对话框里发一条消息**、还顺手触发一次模型回合。
  > 触发它的正是全下：`canAllIn` 对任何有筹码的座位都为真，所以短码时的 `全下` 按钮会亮着，而引擎当时只认"加注到"
  > （筹码不够加注就报错）→ 拒绝 → 退回对话。现在**引擎把"加不了注的全下"当作"跟注全下"**（标准短码推，
  > 记录为 `call`、日志写 `全下 X`），**按钮与引擎不再互相矛盾**，同时客户端也彻底堵住了这条回退路径。
- 想让模型解说某一手时，直接在对话里说话即可（`poker_table` / `poker_equity` 这些工具还在，牌桌状态对模型是共享的）。

数据仍不需要 projection 或 Remote 注册：读走会话事件窗口，写走这条同源路由。

### 健壮性

外壳会断言每个 boot graph 条目都进入 `active`，否则整页显示 “Failed to load plugins”，所以客户端插件绝不能抛错：

- `apply` 整体 try/catch：注册失败只是没有牌桌 UI，不会拖垮页面。
- 牌桌渲染有失败兜底（降级为一行提示）。
- 视图在边界处做形状校验（`looksLikeTableView`），并在渲染内部归一化缺失字段——子组件抛错不会被父组件的 try/catch 接住，
  所以畸形 payload 必须在这里被挡掉。

### 排查客户端是否加载

先**硬刷新**（`Ctrl+Shift+R`）：客户端 boot graph 烧在页面 HTML 里，且首页响应不带 cache-control，
普通 F5 可能命中缓存。之后若只是 `lib/client.js` 的字节变化，客户端 HMR 会自动重载，无需刷新。
控制台可以这样自检：

```js
[__DSH_BOOT__.plugins.some(p => p.id === 'dsh-plugin-poker'),
 !!document.querySelector('style[data-plugin-css^="dsh-plugin-poker"]'),
 document.querySelectorAll('.dshp-felt').length]
```

预期 `[true, true, 若干]`。第一个为 `false` → 页面还是旧 graph，再硬刷新；第二个为 `true` 而第三个为 `0`
→ bundle 已执行但没渲染出牌桌，看控制台里的 `poker:` 警告；`apply` 成功时会打印
`[poker] client half active: 6 table cards + session-header panel`。

主机侧还可以不依赖浏览器直接核对（`/plugins/events` 这个 SSE 端点不鉴权）：

```powershell
curl.exe -N http://127.0.0.1:3080/plugins/events   # data: {"type":"graph", ...} 里应有 dsh-plugin-poker 及其 bundle URL
```

## 打包与开源：它就是一个插件包

这个仓库本身就是**一个可以发布的 DSH 插件包**（零运行时依赖，无构建步骤）：

| 声明 | 作用 |
|---|---|
| `main: lib/index.js` + `exports["."]` | **宿主半**：6 个工具 + `/poker` 路由 + 热重载器。DSH 的 Loader 按名字加载它。 |
| `exports["./client"]` + `dsh.client.platform: "web"` | **浏览器半**：DSH 的 client-modules 扫描到 `dsh.client` 后，把 `./client` 当作一个 bundle 通过 `/plugins` 送到页面（`window.__ModuleLoader__` 经典脚本形式）。 |
| `dsh.bundle.patch: cordis.patch.yml` | **bundle 补丁**：`dsh plugin add` 据此自动把这一行插进 profile，无需手写 YAML。 |
| `peerDependencies["@deepseek-ai/cordis"]`（可选） | 宿主半用的是 cordis 的 `ctx.tools` / `ctx.effect` / `ctx.inject`。标成 optional peer，宿主自带即可。 |

几个刻意的取舍，都是为了"拉下来就能读、就能改"：

- **没有构建步骤**：宿主半是普通 ESM，浏览器半是一段经典脚本（自带 `window.__ModuleLoader__.load(...)` 包装）。
  `npm publish` 发出去的就是真正在跑的那份字节，没有 `dist/` 与源码的偏差。
- **只 require 平台基线**：浏览器半只 `require('react')`，React 在 DSH 的 `PLATFORM_MODULES` 基线里，
  所以不需要声明 `dsh.client.external`（如果你要引非基线模块，才在里面列出精确的包名）。
- **没有运行时依赖**：牌、牌型、策略、教练、蒙特卡罗全部自带，`dependencies` 为空。
- **测试也是纯 Node**：`npm test` 依次跑 5 个 `.mjs`，不需要装任何测试框架，也不需要联网。

发布前要补的三件小事（现在刻意留空，免得写错）：

1. `package.json` 里的 `repository` / `homepage` / `bugs`（指向你的仓库）与 `author`；
2. 想发到 npm 就 `npm publish`（包名不是 scoped，默认就是 public；`publishConfig.access` 已声明）；
3. 每次发版把 `version` 往上走一格，并在 `CHANGELOG.md` 记一行。

> 包名假定为 `dsh-plugin-poker`；如果你要用 scoped 名字（例如 `@you/dsh-plugin-poker`），
> 记得同步改 `cordis.patch.yml` 里的 `name:` 字段与安装命令。

## 已知限制

- **牌局状态在进程内存里**：宿主重启后牌桌消失（重新 `poker_new_table` 即可）。不写会话日志是有意的：卡片数据已随
  `tool/result` 持久化，重放历史牌局不需要重建引擎状态。**热重载不会丢牌桌**，只有重启会。
- **一张牌桌，全场共享**：宿主只维护一张"当前牌桌"，开新桌会替换它（这是"跨会话同步"的实现方式）。
  想同时开两局各打各的，目前不支持。
- **重载的边界是入口层**：`lib/impl.js` 及其依赖（引擎/策略/渲染/牌型/牌）改完即生效；
  但入口层 `lib/index.js`（工具清单、`/poker` 路由、牌桌注册表）和 profile 的 `cordis.patch.yml` 那一行
  仍然需要重启宿主。改这两处时请连着一次重启一起做。
- **热重载靠 mtime + size**：如果某个工具把文件内容改回**完全相同的字节且保留原 mtime**，修订号不变，代码也就不会重载
  （正常编辑器保存不会这样）。要看当前状态用 `plugin.hotState()`。
- **教练是启发式教练，不是解算器**：范围宽度按「位置 + 动作 + 尺度 + 性格」估出来，读牌会错；
  胜率是对抗这个**估计**范围的蒙特卡罗，面板上带 ±误差。它教的是推理方式，不是 GTO 答案。
- **首次安装需要刷新一次页面**：客户端插件的 boot graph 烧在页面 HTML 里。
- `botBrain: 'model'` 时，等待决策的机器人底牌会出现在工具的模型可见文本里（模型需要它才能决策）。
  它在 GUI 里由牌桌卡片渲染替代，但展开原始工具输出仍可能看到 —— 想完全公平就用默认的 `auto`。
- `poker_table { reveal: true }` 会显示所有底牌，仅供调试，正常对局不要用。
